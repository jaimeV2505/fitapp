# Internationalisation (English and Spanish)

The app is available in English and Spanish. The language is chosen with the switcher on **Profile** and on the **sign-in page**, remembered in a cookie (`fitapp-locale`, one year), and defaults to the browser's preferred language.

## How it works

```
src/lib/i18n/
  config.ts       locales, cookie name, Accept-Language parsing
  format.ts       {placeholders} and plurals: {n, plural, one {# set} other {# sets}}
  translator.ts   createTranslator(locale, messages) -> t(key, params)
  messages/en.ts  English dictionary: the source of truth for keys
  messages/es.ts  Spanish dictionary, typed so it must have exactly the same keys
  types.ts        MessageKey: a typo in a key is a compile error
  server.ts       getI18n() / getT() for server components and actions
  client.tsx      <I18nProvider>, useT(), useLocale(), useLocalizedName()
  labels.ts       muscleLabel / equipmentLabel / mealLabel / unitLabel
  names.ts        Spanish names of the built-in routine, foods, days and templates
  errors.ts       maps server error messages to translations
  metadata.ts     titleOf("nav.workout") for page titles
```

The root layout reads the language once and passes its dictionary to the client, so client components translate without any request.

## Rules

1. **No user-visible text in code.** Use `t("namespace.key", params)` in client components (`useT()`) and `const t = await getT()` in server components.
2. **Add the key to both dictionaries.** English first (`messages/en.ts`), then Spanish (`messages/es.ts`). The compiler rejects a missing Spanish key.
3. **Use ICU plurals for counts**, never string concatenation: `"{count, plural, one {# set} other {# sets}}"`. Spanish rules apply automatically.
4. **Dates and numbers take the locale**: `formatShortDate(date, INTL_LOCALE[locale])`, `toLocaleString(intl)`. Never hard-code `en-US`.
5. **Server errors**: throw `new AppError(code, "English message {name}", { name })` and add that English message to `ERROR_KEYS` in `errors.ts` with its translation. A test fails if a thrown message has no translation.
6. **Built-in content names** (routine exercises, plan days, foods, meal templates) go in `names.ts`. Names the user creates, and the wider exercise library, are shown as stored.

## Tests that protect it

`src/lib/i18n/*.test.ts` check that both dictionaries have the same keys and the same placeholders, that every literal key used in the code exists, that every `AppError` message is translated, that the built-in names are covered, and that plurals render correctly in both languages.

## Not translated (on purpose, for now)

- Exercise instructions and the names of the ~600 exercises of the wider library (they come from an English dataset).
- The AI's free-text notes about a meal photo (the model answers in English).

## Adding another language

1. Add it to `LOCALES`, `LOCALE_LABEL` and `INTL_LOCALE` in `config.ts`.
2. Create `messages/<code>.ts` typed as `Messages` and register it in `messages/index.ts`.
3. Add its names to `names.ts` (and `localizeName`) and its error translations.
4. Run `pnpm test`: the consistency tests tell you what is missing.

The end-to-end tests run in English (Playwright's default); they do not depend on your own browser language.
